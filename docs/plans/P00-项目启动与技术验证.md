# P00 项目启动与技术验证

状态：原型交付完成；G00 在 Windows 11 单屏 150% 缩放、SVG 动画路径内通过。进入条件：现有需求基线。完成条件：G00。返回[计划总览](README.md)。硬件与输入法等边界见[验收记录](../verification/P00.md)。

## 1. 目标与边界

从空项目建立可复现的开发入口，并验证桌宠最容易影响后续架构的条件：透明窗口、角色渲染、输入命中、多显示器、资源占用与素材来源。

已确认按 Windows 个人自用版设计，角色为二维二次元／卡通方向。初始无可用模型；实施时采用 Electron + TypeScript + React + 自绘 SVG 动画完成二维动态原型，Live2D 保留专项待验证，不宣称通过或不适用。替代方案的依据见[技术决策](../architecture/P00-decisions.md)。此阶段不接云端 AI、不制作完整聊天业务、不采购或默认承诺正式角色模型；语音与本地 AI 留待后续更新。

## 3. 需要验证的设计

- 立绘窗口与聊天／设置面板分离，弹出面板时可正常输入中文，不影响桌面其他软件。
- 透明区域与角色区域有明确命中规则，拖动和点击不冲突；提供失败时可用的托盘恢复入口。
- 模型渲染、业务协调与未来的 AI 网络请求之间保留边界，不能让耗时任务阻塞动画。
- 动作接口使用语义名称，如 `idle`、`greet`、`thinking`，映射至素材实际动作；缺失动作可回退。
- 本地数据写入用户数据目录，安装目录不承担运行时数据库与设置存储。

## 4. 验收场景

- [x] **P00-A01 / R05**：显示动态测试角色，播放至少待机和一个主动动作；点击角色区域与透明区域，实际结果分别符合设计。
- [x] **P00-A02**：反复打开和关闭面板、拖动角色、最小化其他窗口，角色与输入焦点可恢复；托盘可退出应用。已测方法与输入法边界见验收记录。
- [ ] **P00-A03**：在可用的不同缩放与显示器布局上验证坐标；显示器移除后角色能回到可见区域。缺少多屏设备时记录缺口，完整多屏支持不得宣称已验收。
- [x] **P00-A04**：资源缺失或加载失败时有可见反馈与占位恢复，不出现只能终止进程才能解除的透明遮挡。
- [x] **P00-A05**：记录 5 次启动、10 分钟待机和交互期间的 CPU、GPU、内存、帧率与响应表现。设定该测试环境后续使用的数值预算与测量方法；未经测量不声称轻量。回调采样与窗口可见性的测量边界见记录。
- [x] **P00-A06**：在干净依赖安装状态下，按开发说明能够启动和构建样例，不依赖开发者未记录的全局配置。开发机重新安装依赖通过，不代表全新 Windows 安装验收。
