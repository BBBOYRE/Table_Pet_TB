# P02 可选 API 与角色对话

状态：尚未开始。进入条件：G01 通过。完成条件：G02。返回[计划总览](README.md)。

## 1. 目标与范围

在基础桌宠上增加可启用、可关闭的智能聊天。用户能使用自己的 API，编辑人物性格与背景，并看到文字和已有动作协调表现。

本阶段先接入一个经验证的供应商／协议；多配置与自动路由在 P03。本地 AI 与语音已确定后续更新，首版不安装推理或语音运行时；Harness 不作为此阶段依赖。工作模式与视觉理解在 P04。

云端预算当前未设置，不要求用户填金额才可接入。真实测试时记录模型、调用次数、可获得的用量与费用估算，再确认是否需要预算设置。没有价格信息时不显示为免费。

## 3. 接口与状态约定

模型适配层负责连接、数据格式与能力描述；聊天服务负责会话、上下文和本轮取消信号；动画执行器只接受已注册动作。

请求至少具有会话标识、请求标识、角色档案版本、模型选择和生命周期状态。请求取消后，迟到的响应不能继续写入当前回复或触发新动作；已经播放的动作不能回溯撤销。

模型请求只从用户启用的 AI 入口触发。关闭 AI 后停止新请求、取消在途请求和待发送队列，保留未发送输入与本地资料；已发送给供应商的内容不能撤回。不因失败自动启用其他服务。

切换安静、问候或丰富养成模式不自动调用 AI；首版主动问候与养成反馈沿用 P01 的本地事件策略。用户主动聊天时，人设与模式的频率约束共同生效。

API 凭据不存入普通设置、角色档案、聊天导出或日志。前端通过受限接口调用服务，不直接拿到凭据。接入协议在本阶段实际验证，不能仅凭“兼容接口”推断工具调用可用。

## 4. 人物设定与记忆

- 每轮读取有效的角色档案，并形成不可变版本快照；编辑中的字段不进入请求。
- 保存新设定后从下一轮生效。当前轮沿用旧快照，避免流式回答中途变更人物。
- 角色设定在历史压缩后重新加入有效上下文；旧会话描述不得覆盖新档案。
- 试聊与正式会话分开，不自动写入长期记忆。
- 记忆先支持用户明确保存、编辑、删除的事实；复杂自动提炼延后。
- 模型表达会有波动，采用样例人工评估；“档案正确发送”与“角色表现自然”分别记录。

## 5. 验收场景

- [ ] **P02-A01 / R01、C10**：从未配置到启用、关闭再重启的完整流程中，基础桌宠始终可用；预算留空可正常接入；编辑档案或切换互动模式不产生 API 调用。
- [ ] **P02-A02 / R02、R04**：使用实际支持的 API 完成流式聊天、停止和重试；无效凭据、超时和服务错误有明确反馈，失败消息不伪装成功。
- [ ] **P02-A03 / R01、C05**：在流式回复和排队状态关闭云端 AI，之后无新请求、无迟到动作；基础动画继续运行。
- [ ] **P02-A04 / R09**：分别使用两份明显不同的性格背景进行试聊；检查请求档案与人工表达效果。保存修改后下一轮使用新版本，当前轮保持原版本。
- [ ] **P02-A05 / R05**：正常动作能执行；未知动作、越界参数和短时间重复调用被处理；模型只返回实际支持的动作集合，执行失败不阻断普通文本回复。
- [ ] **P02-A06 / R09**：重启、切换可用模型标识和压缩历史后档案仍正确；正式会话不混入试聊记忆。多供应商切换在 P03 追加验证。
- [ ] **P02-A07**：检查会话导出、错误日志和设置文件中无 API Key；删除指定会话／记忆后不再进入新请求。
