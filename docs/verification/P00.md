## 性能方法与结果

五次启动分别使用新进程与独立数据目录，但操作系统文件缓存未清空，不能称为重启机器后的冷启动。启动时间从测试脚本创建进程开始，到桌宠界面发送就绪事件结束，不代表第一帧在物理屏幕上显示的精确时间。

待机仅保留桌宠和托盘，控制台关闭；交互测量打开控制台，每约三秒切换一次动作。首次观察中途出现第二个渲染窗口，其混合数据被排除；正式基线使用仅在测试模式生效的待机场景锁定，并检查每条样本的窗口数和动作。CPU 和内存每 10 秒读取 `app.getAppMetrics()`，丢弃首条；GPU 使用 Windows 原始引擎计数器，以该应用进程的运行时间差除以时间差，合并同一物理引擎后取最繁忙引擎。其他桌面程序仍在运行，未宣称严格隔离实验。

| 项目 | 实际结果 |
|---|---|
| 五次启动 | 227 / 180 / 198 / 223 / 239 ms，中位数 **223 ms** |
| 待机时长与采样 | 约 620 秒运行，首末样本间 **610 秒**；62 条进程样本、60 条 GPU 样本；全程样本均为一个窗口、`idle` 动作 |
| 待机 CPU / GPU | CPU 原值总和平均 1.10；最繁忙 GPU 引擎平均 1.24%、最高 5.03% |
| 待机工作集总和 | 平均 **361.29 MiB**，峰值 **431.08 MiB**；首个稳态样本 395.20 MiB，末样本 340.05 MiB |
| 最近完成的回调采样 | 待机记录均值约 240.09 Hz；有后台节流和旧采样值限制，不能视为持续显示帧率 |
| 交互样本 | 约 60 秒，20 次控制台动作切换；5 条 GPU 样本 |
| 交互 CPU / GPU | CPU 原值总和平均 5.96；最繁忙 GPU 引擎平均 6.03% |
| 交互工作集总和 | 平均 **628.56 MiB**，峰值 **653.07 MiB**（包含控制台） |
| 点击至动作状态 | 平均 36.18 ms，P95 27.75 ms；20 次样本，P95 排除最慢一次，样本量较小 |

可复核的脱敏数值见 [P00-metrics.json](P00-metrics.json)。

指标解释：

- CPU 是 Electron 返回的各进程 `percentCPUUsage` 总和，不能直接与任务管理器整机百分比互换。
- 内存是各进程工作集总和，包含可能重复计入的共享内存，不是独占物理内存；瞬时工作集回收也不等于泄漏修复。
- 帧率字段保存最近一次完成的 1.5 秒 `requestAnimationFrame` 回调采样；后台节流可能让后续采样暂停而保留旧值，因此不能视为持续显示帧率或卡顿统计。它不是屏幕录像逐帧分析，也不保证每个回调都产生新的画面。
- GPU 是本应用最繁忙引擎的使用率，不是把 GPU 进程 CPU 当作 GPU 使用率，也不是整机显卡利用率。
- 点击响应包含 Playwright 点击调度、IPC 和 DOM 状态观察，作为同方法回归指标，不等于人类感知延迟。

待机复测后段的 CPU／GPU 降低，表现出后台节流迹象；本次没有同步记录系统窗口遮挡状态，不能据此将平均值当作全程前台动画成本。交互测量和峰值用于提供更保守的参考，后续比较必须记录窗口可见性。

原始记录在本机 `.local/verification/benchmark` 和 `.local/verification/interaction-*`；不提交其中的用户目录、进程号或本机绝对路径。可分享的数值摘要另存于同目录下的 `P00-metrics.json`。

### 后续回归预算

以下是本机、相同测量方法下的工程预警阈值，用于发现 P01 新增逻辑导致的明显退化；不是用户已确认的长期性能目标，也不是跨设备承诺。

| 指标 | 预警阈值 |
|---|---|
| 五次启动中位数 | 不超过 1000 ms |
| 仅桌宠待机的进程工作集总和 | 平均不超过 500 MiB，峰值不超过 600 MiB |
| 控制台动作交互的进程工作集总和 | 平均不超过 750 MiB，峰值不超过 850 MiB |
| CPU 原始百分比总和 | 待机平均不超过 6；交互平均不超过 8 |
| 应用最繁忙 GPU 引擎 | 待机平均不超过 8%；交互平均不超过 10% |
| 点击到动作状态 P95 | 不超过 150 ms |

帧率保留原始回调采样，不据此设置“始终 240 FPS”目标；P01 应建立可见窗口下的新鲜采样和动画节奏目标。十分钟记录不足以证明没有内存泄漏，P06 仍需长期运行和休眠恢复验证。

## 已修正问题与后续边界

1. Windows 重建透明窗口后鼠标转发可能不再到达：增加仅限本窗口范围的光标探测，并限制子图形移出事件的处理。
2. 自定义拖动期间避免透明穿透；松开后保存并回到可见工作区，超时可恢复。
3. npm 从 PowerShell 7 环境启动系统 PowerShell 时模块搜索路径不同：运行时安装器显式补入系统模块路径。
4. 当前高刷新率下持续动画仍有常驻资源成本。P01 应评估动画节奏、隐藏暂停和资源释放，并增强帧率采样的新鲜度与窗口可见性记录，暂不称为“轻量”。
5. 未覆盖真实多屏／混合 DPI、输入法候选框、休眠唤醒、全天运行、Windows 10、ARM64 和 Live2D。增加这些支持声明前需补测；控制台“安静展示”也不是三种主动互动模式。

**G00：在 Windows 11、单屏 150% 缩放、SVG 动画路径内通过，P00 原型交付完成。** 核心窗口交互、动态渲染、恢复、可复现构建和性能记录已有证据，可以进入 P01。该结论不包括真实多屏、输入法候选框、Live2D、长期稳定性或安装包；未覆盖项保持待验证。
