# P00 阶段总结与思考

日期：2026-10-20。复盘对象：`c71865d` / 0.0.1。依据为[验收记录](../verification/P00.md)、[性能摘要](../verification/P00-metrics.json)、[技术决策](../architecture/P00-decisions.md)及当前源码。本次进行文档复盘和计划细化，没有新增功能或重跑性能实验。

P00 已建立可以继续开发的 Windows 桌宠底座。G00 的结论限定在 Windows 11、单屏 150% 缩放与 SVG 动画路径；用户是否喜欢角色、是否愿意长期保留在桌面、主动互动是否舒适，仍需 P01 试用验证。当前成果可以进入下一阶段，但不能据此认为整个产品已完成大半。

## 1. 当前成果对应了哪些需求

| 用户目标 | P00 实际成果 | 后续需要完成 |
|---|---|---|
| 无 API 也能使用 | 启动、动画、点击拖动、设置和托盘均不依赖模型 | P01 完整本地互动；P02 启用与关闭 AI 时继续保持基础功能 |
| 二维动态角色 | 自绘“小芽”，待机、问候、开心、思考可播放 | 正式视觉方向、更多表情与动作质量；Live2D 专项尚未验证 |
| 可选陪伴方式 | 可隐藏气泡，保留动作 | P01 安静、问候、轻量养成的真实行为差异与免打扰 |
| 人物性格与背景 | 尚无档案编辑和保存 | P01 存储与编辑，P02 用于模型对话 |
| Agent 调用角色动作 | 已有语义动作名称与校验 | P02 接入模型调用、取消和异常处理 |
| 提醒、便签、打开应用 | 尚未实现 | P03 |
| 查看页面、截图快捷工作 | 尚未实现 | P04；持续查看按 P05 评估 |
| 语音、本地 AI | 按已确认范围暂缓 | 后续更新 |

“安静展示”目前只控制气泡可见性；原型动作由按钮或鼠标触发。不能把这些分别等同于完整安静模式或 Agent 能力。

## 2. 有证据支持的阶段结论

透明窗口、角色命中、空白穿透、拖动、焦点保持、托盘驻留与退出、设置重启恢复、素材异常和渲染崩溃恢复已有验证。5 项单元测试、8 项桌面测试、类型检查和构建通过；重新安装依赖后能运行。真实 Windows 鼠标测试发现过事件转发问题，表明窗口层验证需要包含操作系统输入路径。

框架可以继续沿用。Electron + React 已支撑当前交互；SVG 动画解决了没有可用模型时的验证需求。现有信息没有证明需要立即换框架，也没有证明 Live2D 不适用。正式角色制作与应用逻辑可以分开推进，语义动作契约应保留。当前仅支持 `svg-prototype`，新增模型格式仍需实现适配，不能宣称已经支持任意换皮。

用户数据写在用户目录，动作由主进程校验，界面通过受限桥调用，基础程序无需模型。这些边界适合保留到后续阶段。P01 按实际业务拆分窗口、动作、事件策略和存储即可，无需提前搭建通用插件市场、多 Agent 系统或复杂数据库框架。

## 3. 性能数据意味着什么

| 数据 | 本次结果 | 能支持的判断 |
|---|---|---|
| 五次启动中位数 | 223 ms | 在本机文件缓存未清空的条件下，启动至界面就绪较快；不是物理首帧或冷启动结果 |
| 单窗口待机工作集总和 | 平均 361.29 MiB，峰值 431.08 MiB | 已有数百 MiB 的常驻成本，值得优化；包含共享页重复计入，不能视为独占内存 |
| 控制台动作交互工作集总和 | 平均 628.56 MiB，峰值 653.07 MiB | 打开控制台时占用更高；两个不同场景的均值差不能直接归因于某一个组件 |
| 待机与交互 CPU 原值总和 | 平均 1.10 / 5.96 | 可在相同方法下比较；不能直接套用任务管理器整机百分比 |
| 应用最繁忙 GPU 引擎 | 平均 1.24% / 6.03% | 后台节流影响平均值，不代表全程可见动画成本 |
| 回调采样 | 约 240 Hz | 是最近完成的 rAF 采样，可能陈旧，不能写成持续 240 FPS |
| 动作观察延迟 | 平均 36.18 ms，P95 27.75 ms | 20 次样本可作初步回归参考；P95 排除最慢一次，平均值大于 P95 不构成计算矛盾 |

原型有足够响应能力继续开发，轻量化与长期稳定性仍需证据。十分钟内未见持续上升不能证明没有泄漏；现有预算是工程预警线，不是用户接受的常驻资源上限。对于陪伴软件，低干扰与较低的长期资源占用应优先于追求高刷新数字。

下一次性能验证先补齐测量口径：记录窗口数、可见／隐藏状态、显示器刷新率、采样完成时间和样本年龄；无法确认系统遮挡时标记未知。过期帧率记为不可用，避免重复旧数值拉高均值。分别记录可见待机、隐藏／后台、面板打开与动作交互，保留原始数据和场景标识。

优化按单项改动对照：先评估诊断采样按需启用、隐藏或最小化面板暂停预览动画、帧节奏和光标探测频率。窗口隐藏策略不能破坏托盘恢复或穿透。若测量完善后仍超过确认的目标，再比较渲染实现或宿主框架；当前不作“换框架一定更省”的结论。

## 4. 产品体验还缺少什么

目前控制台适合展示动作和检查技术状态。P01 日常入口应以桌面角色和简单设置为中心，首次使用能直接出现角色，诊断功能作为次级入口。昵称、称呼和简短反馈比增加更多测试按钮更能帮助建立角色感，但其实际效果需要用户试用。

陪伴模式应决定主动程度，人物档案决定角色表达，两者独立保存：

| 模式 | P01 应呈现的区别 | 需要避免的问题 |
|---|---|---|
| 安静陪伴 | 低干扰待机，不主动闲聊；点击仍有反馈 | 把“安静”误做成无法互动 |
| 偶尔问候 | 在允许时段低频触发本地问候，有冷却与内容去重 | 频繁重复同一句话、恢复后补发多条 |
| 丰富养成 | 同一事件序列产生额外本地反馈，显示轻量互动状态 | 只换模式名称、为增加互动制造惩罚或催促 |

建议新用户默认安静陪伴，这是设计建议，尚非用户指定的默认值。升级现有配置时应保留偏好，不能借默认值覆盖用户已选择的设置。关闭丰富模式保留状态，免打扰优先于主动事件；未来用户创建的到期提醒采用独立策略。

当前没有收到足以评价角色审美、动作自然度和打扰程度的试用反馈。后续试用重点记录：是否遮挡常用位置、气泡多久开始显得重复、三种模式是否容易理解、是否愿意保持运行、角色风格是否符合预期。这些属于体验验证，自动化测试不能代替。

## 5. 从代码复查得到的改进项

以下是静态复查结论或待验证假设，不是新一轮运行测试结果，也不代表已发生数据丢失。

| 优先时机 | 发现与影响 | P01 对应工作与完成证据 |
|---|---|---|
| 引入角色档案前 | `parseSettings` 对不支持的版本返回默认值；有效 JSON 的结构问题不会进入损坏备份分支。后续保存可能覆盖原文件 | T04：区分缺失、损坏、旧版本与未知新版本；迁移前保留原始文件，未知版本不能静默覆盖；验证旧版位置和偏好可保留 |
| 档案保存界面交付前 | 设置写入失败目前仅输出控制台信息，命令成功响应没有表达持久化失败 | T04、T05：区分内存更新与已保存，保存失败可见且保留编辑内容；模拟写入失败后可重试 |
| 增加主动互动前 | 现有动作机制主要是冷却和定时回待机，尚无完整的事件优先级和模式取消规则 | T02、T03、T07：明确拖动／用户点击／主动事件的优先级；模式切换、免打扰和休眠恢复不积压事件 |
| 性能优化前 | 普通运行也会执行定期 rAF 诊断；50ms 光标探测用于实际兼容性补偿 | T01、T08：先测开销，再按需采样或调节频率；不能把兼容性补偿直接删掉；验证快速移入、点击和拖动边界 |
| 宣称长期可用前 | 现有测试只有短时原型证据，且缺少真实输入法与多屏设备验证 | T08：至少一小时运行、反复开关设置面板、检查资源释放；中文档案编辑补真人输入法流程；缺设备时保留支持范围说明 |

存储层继续使用 JSON 仍然可行，关键是数据生命周期和失败处理。仅为了新增档案就改用 SQLite，并不能自动解决保存失败、结构迁移或误覆盖问题。

## 6. 开发过程的经验

本次测试经历了角色内部移出事件、透明窗口重建后转发缺失、原生测试时光标被移动、测试框架保留崩溃 target 等问题。后续诊断先区分应用行为、自动化工具状态和外部操作；原生测试只对自己的窗口点击，遇到光标干扰应终止该次操作，不能通过放宽断言隐藏问题。

第一次待机测量中途出现第二个窗口，后续固定待机场景并重测才形成可用基线。以后先做短时测量工具自检，确认数据路径、场景标识和异常退出，再启动长时验收。测量中发生场景变化的记录应另列，不能混入目标场景平均值。

短周期功能演示应早于耗时的完整验收，让用户先反馈角色与交互，再完成冻结版本上的测试。完成一批后报告实际成果和限制；对尚未提供体验反馈的设计，保持可调整，不将其写成已经确认的产品选择。

## 7. P01 建议实施顺序

沿用原有任务编号，不新增阶段，也不改变 API、工具、截图、语音或本地 AI 的归属。以下为下一阶段执行细化，P01 尚未开始。

| 批次 | 对应任务 | 可检查的成果 |
|---|---|---|
| 1. 稳定基础与数据 | T01、T04 | 整理窗口／业务边界；保留现有配置；角色档案与互动状态结构；迁移及保存失败处理；补测量状态 |
| 2. 一条完整互动路径 | T02、T03、T05、T06 | 桌面直接使用；点击反馈、动作切换、称呼替换；编辑保存和放弃更改；托盘与免打扰 |
| 3. 三种模式 | T07 | 同一事件序列下表现不同；切换、冷却、时段、轻量状态和重启恢复可验证 |
| 4. 日常试用验收 | T08 | 离线试用、至少一小时运行、设置面板反复开关、资源和恢复复测，以及用户体验反馈 |

其中模式规则适合用可控时间与确定的事件序列验证，避免靠真实等待数小时检查问候频率；一小时真实运行仍用于资源释放和稳定性，不能由模拟时间代替。

P01 的完成判断应围绕一次完整使用过程：无需 API 启动，角色能安静陪伴，用户能够编辑并保留称呼与背景，切换模式确实改变行为，退出重启后设置仍在，长时使用没有失控事件或不可恢复的窗口问题。阶段完成后再进入 P02 对话接入。
